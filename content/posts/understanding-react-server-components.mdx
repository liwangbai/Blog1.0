React Server Components (RSC) represent a paradigm shift in how we build React applications. Let's understand the mental model.

## The Core Idea

RSC allows components to run **only on the server**. They never ship JavaScript to the browser. This means:

- Smaller bundle sizes
- Direct database access from components
- No client-side data fetching waterfall

## Server vs Client Components

```
Server Component (default)     Client Component ('use client')
─────────────────────────     ─────────────────────────────
Runs on server                 Runs on server AND browser
Can be async                   Cannot be async
No hooks/state                 Can use hooks/state
Direct DB/filesystem access    Cannot access server resources
Serialized to client           Hydrated on client
```

## When to Use Client Components

Only add `'use client'` when you need:

1. **Event listeners**: `onClick`, `onChange`, etc.
2. **Hooks**: `useState`, `useEffect`, `useContext`
3. **Browser APIs**: `localStorage`, `window`, `document`

## Composition Pattern

The key insight: Server Components can render Client Components, but Client Components cannot directly import Server Components. Instead, pass Server Components as children:

```tsx
// ServerComponent.tsx
import { ClientWrapper } from './ClientWrapper';

export function ServerComponent() {
  const data = await fetchData();
  return (
    <ClientWrapper>
      <StaticContent data={data} />
    </ClientWrapper>
  );
}
```

This pattern keeps data fetching on the server while enabling interactivity where needed.
